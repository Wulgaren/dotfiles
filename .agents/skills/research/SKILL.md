# Research

Every **load-bearing** fact (one the user's decision turns on) gets placed on the source ladder and gets a critique search before it reaches the answer.

Three traps drive the wrong answer here. A fetched page feels like a source, so "I read a page" passes for "I verified the claim". Confirmation search is cheap and critique search is not, so under pressure only the cheap one runs. When two sources disagree, picking the one that fits the story so far is easier than reporting the conflict. Each step below closes one of these.

## Source ladder

Label every fact with its rung.

1. **Primary**: the paper itself (abstract, methods, tables), the manufacturer's spec page, the vendor's price page, the original document.
2. **Adjudicating**: systematic reviews, meta-analyses, regulator filings, independent test labs.
3. **Summary**: comparison sites, review blogs, aggregators, wikis.
4. **Snippet**: search-result text. A lead to a page, nothing more.

- A rung-3 number reaches the answer only after you trace it to rung 1 or 2.
- Affiliate links or "as an Amazon Associate" on a summary page are a bias flag: open the primary listing too.
- Two rung-3 pages that disagree send you to rung 1. Confidence of tone is not a tiebreaker.

## Steps

1. **Name the decision.** What will the user do with the answer: spend money, change behaviour, repeat it to someone? Split the question into the claim (checkable) and the advice (opinion is allowed). Done when you can list the load-bearing facts.
2. **Chase the cited source.** When the user cites a person (a dentist, a colleague, a forum) or a document, that citation is the best lead. Find what exactly was claimed, or ask. Done when each cited claim is stated precisely or marked unknown.
3. **Climb the ladder.** Trace each load-bearing fact to rung 1 or 2. Done when every one carries a rung label.
4. **Critique search.** For each load-bearing fact, run the adversarial checks below. Done when every check has run for every fact, with its result noted.
5. **Answer.** Write it per Reporting. Done when the done test passes.

## Adversarial checks

- **Critique**: search for the attack, not the support: `<study> criticism`, `<paper> correction`, `<product> problems`, `<thing> recall`.
- **Contradiction**: look for a review that found the opposite, or a newer paper. Confirm the newer one actually supersedes the older.
- **Arithmetic**: sanity-test every composite index, percentage, and ranking. Parts sum correctly, no percentage over 100, the stated denominator matches the text.
- **Funding**: label manufacturer-funded evidence as such.
- **Independence**: two reviews built on the same trials are one body of evidence, not two votes.
- **Version**: for fast-moving topics, confirm the date, model year, or software version on the page.

## Reporting

- **Conflict is the deliverable.** When sources disagree, give each position with its source and date, why they may differ (different trials, definitions, funding, data age), which you weight more and why, and what would settle it. A visible contradiction is a correct answer; a smoothed one is fabricated.
- **Cite the primary**, not the summary that mentioned it. Add the date checked for anything that moves: prices, specs, benchmark scores.
- **Name the gaps.** State what you could not verify and what would verify it. "Not checked" is a useful result.
- **Corrections lead.** When a later check overturns something you already told the user, open with the correction and name what changed. The earlier confident statement does not get to stand.

## Done test

Reread every factual sentence: which rung is it from, and did its critique search run? A sentence you cannot place gets softened to what you know, or cut.
